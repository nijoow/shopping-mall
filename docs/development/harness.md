# 실행·검증 하네스

기준: 2026-10-03. 하네스는 작업 규칙·실행 명령·테스트 격리·CI·완료 증거를 뜻해. 앱 기능과 자동 에이전트 시스템을 추가하는 작업은 아니야.

## 점검에서 확인한 문제와 조치

| 코드/설정 근거                                                                  | 조치                                                                           |
| ------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| AGENTS에 프로젝트 책임·검증·문구 기준 부재                                      | 짧은 코드 지도, 변경 규칙, 검증 선택 기준 추가                                 |
| README의 첫 로컬 버전 설명, 제거된 관리자·포인트를 참조하는 BACKLOG             | 실행 문서 갱신, 구 백로그 보관, 현재 로드맵 분리                               |
| `dev` 기본 3000 vs 기존 HTTP 스크립트 기본 3100, 테스트가 기존 서버 설정에 의존 | 임시 포트·서버·SQLite를 소유하는 HTTP 실행기 추가                              |
| PostgreSQL 테스트가 `POSTGRES_URL`을 fallback으로 사용                          | 테스트 전용 변수만 허용, 기본 단위 테스트에서 분리, 명령 실행 시 미설정은 실패 |
| 타입 검사 전에 Next 라우트 타입을 생성하지 않음                                 | `next typegen && tsc --noEmit`                                                 |
| 모델과 이미지 연결 검사가 없음                                                  | 기존 모델 3개와 현재 상품의 파일·GLB·재질 계약 검사                            |
| CI가 HTTP와 실제 PostgreSQL 동시성 검증을 생략                                  | CI 임시 PostgreSQL 서비스와 HTTP 테스트 단계 추가                              |
| 릴리스가 커밋 메시지를 셸에 삽입하고 버전을 추측                                | `v*` 태그로만 실행, package 버전 대조, 입력은 환경 변수로 전달                 |

## 일상 작업

아래 `yarn`은 `node .yarn/releases/yarn-4.0.2.cjs`로 대체해도 돼. 설치된 전역 Yarn 버전에 의존하지 않아.

| 명령                 | 확인하는 것                                                | 확인하지 않는 것                      |
| -------------------- | ---------------------------------------------------------- | ------------------------------------- |
| `yarn check`         | 타입 생성·타입 검사·린트·단위 테스트·에셋 계약             | 실제 브라우저, 실제 PostgreSQL, OAuth |
| `yarn check:full`    | check + 프로덕션 빌드 + HTTP 흐름                          | 브라우저 조작·시각 품질·실제 OAuth    |
| `yarn test:http`     | 기존 빌드로 전용 서버 시작 → API 검증 → 종료·임시 DB 삭제  | 기존 개발 서버·운영 DB                |
| `yarn test:postgres` | 두 PostgreSQL 연결의 저장·동시 주문·중복 환불·디자인 충돌  | 제공자 로그인·브라우저                |
| `yarn assets:check`  | 상품 이미지 존재, GLB 헤더·길이·메시·편집 재질, v1/v2 경로 | 실루엣·UV·봉제·빛·각인 가독성         |

`check:full`은 빌드를 변경하므로 같은 체크아웃에서 빌드를 동시에 두 번 돌리지 마. 기존 개발 서버를 임의로 종료할 필요는 없어. HTTP 실행기는 생성한 자식 서버만 종료하며 기존 `.data`를 삭제하지 않아. 실행이 강제 종료되면 OS 임시 폴더의 `nijoow-http-*` 중 해당 실행의 폴더만 정리해.

## 변경별 최소 검증

| 변경                    | 최소 증거                                                             |
| ----------------------- | --------------------------------------------------------------------- |
| 문서                    | 경로·명령·링크·사실관계와 diff 확인                                   |
| UI 문구                 | `check`, 영향을 받는 성공·오류·빈 상태 화면 확인, 긴 문구 줄바꿈 확인 |
| 가격·주문·소유권·API    | `check:full`, 관련 실패/경쟁 조건 테스트                              |
| DB 어댑터·SQL·계정 이관 | `check:full` + 전용 DB `test:postgres`                                |
| 3D·에셋                 | `check`, 대표/측면/후면/밑창, 색/재질/각인·저장/재열기·PNG 실제 화면  |
| 로그인                  | 관련 자동 검사 + 제공자별 실제 성공/취소/실패/이관 증거               |
| 배포                    | 위 변경별 검사 + CI + 정확한 커밋의 READY + 운영 주요 경로 확인       |

## PostgreSQL 테스트

- 테스트 URL은 전용 개발 DB 또는 폐기 가능한 로컬 컨테이너를 가리켜야 해. `.env.local`이나 운영 `POSTGRES_URL`을 자동 로드하지 않아.
- 새 DB의 `nijoow_demo` 스키마는 테스트용 `NIJOOW_POSTGRES_URL`을 설정해 `yarn db:setup`으로 초기화해. 평소 앱이 사용하는 연결을 변경하지 않도록 해당 명령 범위에만 주입해.
- `NIJOOW_TEST_POSTGRES_URL`을 설정한 뒤 `yarn test:postgres`를 실행해. 값이 없으면 성공/skip으로 오인하지 않도록 명령이 실패해.
- 테스트 종료는 자신이 생성한 workspace 데이터만 정리해. 도중 실패 시 생성/정리 범위를 확인하고 운영 DB 전체 삭제·truncate로 대응하지 마.
- CI는 비밀값이 필요 없는 PostgreSQL 16 서비스 컨테이너를 사용하고 job 종료 시 폐기해. [GitHub 공식 서비스 컨테이너 안내](https://docs.github.com/en/actions/tutorials/use-containerized-services/create-postgresql-service-containers)를 따른 설정이야.

## UI 검수와 재현 기록

현재 저장소에는 자동 브라우저 시나리오가 없어. 성공한 API 테스트를 화면 검증 완료로 표현하지 마. UI 자동화는 로드맵 P1-2에서 추가해.

기본 화면 폭은 데스크톱 1440과 1280, 보조 확인은 390이야. 실제 기기 검수는 별도로 기록해. UI/3D 작업에서 다음을 남겨.

- 브랜치/커밋, 경로, viewport, 게스트/로그인 여부와 재현 순서.
- 기대 결과와 실제 결과, 콘솔 오류, 필요한 캡처. 자료는 Git 제외 `artifacts/<날짜>/`에 보관해.
- 실패 화면을 재현할 때 기존 사용자의 주문·디자인을 사용하지 마. 테스트의 자신의 공간을 사용해.
- 성능은 기기·네트워크·콜드/웜 상태와 측정 방법을 함께 기록해. 프레임·용량 수치로 육안 품질을 대신하지 마.

## CI와 배포 경계

CI는 PR(main/develop)과 main/develop push에서 같은 검사들을 실행해. 최소 권한은 contents:read야. 릴리스는 package 버전과 일치하는 `v0.2.0` 같은 태그를 푸시했을 때만 생성해. 태그/원격 푸시/배포는 현재 사용자 요청 범위에 포함될 때 진행해.

단위·HTTP·PostgreSQL·브라우저·OAuth·운영 검증은 서로 다른 증거야. 완료 보고에 실행한 것과 미실행을 구분해. 이번 하네스 변경의 원격 CI는 커밋·푸시 후 별도 확인해야 해.

## 이번 로컬 확인 결과

2026-10-03, 로컬 Node v25.8.2에서 확인했어. CI 기준 Node 22 / PostgreSQL 16 실행은 원격 적용 후 확인 대상이야.

- `check`: 타입 생성·타입 검사·린트·단위 테스트 13개·상품 7종/모델 3개/이미지 참조 10개 검사 통과.
- `build`, `test:http`: 통과. 소유권·잘못된 입력·타 origin 차단·디자인 저장·응답 유실 복구·중복 주문·배송/환불·초기화·동시 주문 검증. 임시 서버/DB 정리 확인.
- PostgreSQL 실행기: 테스트 URL 미설정 시 실패 확인. 운영 변수와 이전 실행 플래그만 있어도 연결하지 않는 것 확인.
- 실제 PostgreSQL 재실행: 로컬 PostgreSQL 14의 `libicui18n.74.dylib` 누락으로 임시 DB 기동 실패. Docker daemon도 실행 중이 아니어서 완료하지 못했어. 운영 DB로 대신 검증하지 않았어.
- CI YAML 파싱·문서 내부 링크·diff 검사 통과. 원격 CI·릴리스·사이트 문구 변경·배포는 이번에 실행하지 않았어.
