# 네이버 실제 로그인 확인

> 과거 검증 기록이야. 2026-10-05 사용자가 OAuth를 제거하는 범위로 변경했으므로 아래 인증 대기는 현재 완료 조건이 아니야. 최신 결정과 구현 검증은 [방문자 체험 전환 기록](2026-10-05-visitor-only.md)을 확인해.

2026-10-04, 사용자가 로컬 검증 화면에서 네이버 로그인을 진행한 뒤 확인했어.

- 네이버 계정 레코드와 연결된 회원 공간이 생성됐어. 개인 식별값은 이 기록에 포함하지 않았어.
- 실제 브라우저의 마이페이지에서 로그인된 회원 상태와 로그아웃 버튼을 확인했어.
- 같은 인증 코드에 대한 콜백이 두 번 도착했고, 뒤의 요청은 이미 사용된 코드에 대해 네이버가 `invalid_request / no valid data in session`을 반환했어. 첫 인증 성공과 별개로 `Configuration` 오류 화면이 표시됐어.
- 이전에 같은 localhost origin에서 다른 프로젝트의 서비스 워커 오프라인 화면이 나타난 기록이 있어. 그 프로젝트의 navigation preload와 API 제외 처리도 확인했지만, 이번 콜백 중복의 직접 원인으로 단정하지 않았어. 다른 프로젝트 파일·브라우저 저장 데이터를 변경하지 않았어.

## 수정과 재확인

로그인 페이지에서 실제로 검증된 세션이 있으면 안전한 복귀 경로로 이동하도록 수정했어. 오류 쿼리만으로 인증을 우회하거나 콜백 코드를 재사용하지 않아. `/auth/*`, `/api/*` 복귀 경로는 마이페이지로 바꿔 자기 자신으로 반복 이동하지 않도록 했어.

유효한 네이버 세션을 가진 브라우저로 `auth/login?error=Configuration`을 다시 열었을 때 마이페이지로 이동하는 것을 확인했어. 이 결과는 네이버 로그인 성공과 세션 유지의 증거야.

기존 데이터가 있는 게스트의 계정 이관, 로그아웃/재로그인, 실제 동의 취소는 아직 별도 실검증 대상이야. Google의 삭제된 클라이언트 교체와 Kakao 실제 로그인도 남아 있어.

검증: `check:full` 통과(타입·린트·26개 핵심 테스트·에셋·빌드·HTTP·브라우저 3흐름). 인증 복귀 경로의 외부 주소 및 내부 로그인 반복 경로 차단 테스트도 통과했어. 실제 로그인 브라우저에서 오류 쿼리 재진입 후 회원 상태 유지까지 확인했어.
