# 방문자별 내 공간으로 전환

기준: 2026-10-05. 사용자가 포트폴리오의 로그인 필요성을 재검토하고 OAuth 전부 제거·방문자별 저장·공유/PNG 유지로 범위를 변경했어. 소셜 인증 대기는 현재 완료 조건에서 제외했어.

기능 커밋: `83d544b` (`codex/editorial-storefront`). 이전 기능 기준은 `120f6cc`야.

## 구현

- 로그인/로그아웃 UI·Auth.js와 종속 인증 패키지·제공자 설정·인증 API·계정 생성/병합을 제거했어. 이전 `/auth/*` 주소는 query를 전달하지 않고 `/my-page`로 이동하며 `/api/auth/*`는 404야.
- 내 공간은 기존 `nijoow-demo-v2`의 256-bit 임의 토큰으로 구분해. 쿠키는 HttpOnly/SameSite=Lax, 운영은 Secure이고 DB는 SHA-256 해시를 저장해. 응답은 private/no-store야. Auth.js 쿠키·계정 ID·표시 이름으로 자료를 복구하지 않아.
- 유효한 예전 회원 쿠키는 자기 공간 한 행만 방문자로 전환해. ID·토큰·디자인·찜·장바구니·주문·재고·공유 스냅샷을 유지하며 계정 행과 다른 예전 공간을 병합하거나 삭제하지 않아. 전환은 트랜잭션으로 수행해.
- 모든 현재 방문자에 저장·공유 제한을 적용해. 새 생성과 예전 공간 전환은 생성/용량 제한을 따르고 기존 방문자는 용량 상한에서도 재방문할 수 있어.
- 쿠키 삭제·브라우저/기기 변경·마지막 접근 후 7일 초과 시 기존 비공개 목록에 접근할 수 없어. 만료/잘못된 토큰은 새 공간을 만들고 예전 자료를 공개하지 않아. 공유 링크 7일 읽기 전용 스냅샷과 PNG는 유지해.
- 예전 `accounts`/`account_id` 스키마는 백업/자료 호환을 위해 보존해. 미전환 계정 공간은 정리 대상에서 제외하며 유효한 쿠키로 전환한 공간은 이후 방문자 만료·정리 규칙을 따라. 자동 정리 스케줄은 없어.
- 환경 예시는 OAuth 키를 제거하고 선택적 `NIJOOW_APP_URL`로 외부 앱 origin을 설정해. 기존 비밀 파일과 사용자 DB는 변경하지 않았어.

## 검증

로컬 Node v25.8.2 / Chromium / PostgreSQL 16에서 확인했어.

- `check`: 타입 생성·TypeScript·ESLint·단위 25개·상품 7종/모델 5개/이미지 참조 12개 통과. 라우트 제거로 남은 옛 생성 타입은 `.next/types`/`.next/dev/types`만 정리하고 다시 생성했어.
- 프로덕션 빌드 통과. 인증 API는 라우트 목록에 없고 이전 UI 주소에는 호환 redirect만 남아.
- 격리 HTTP: 쿠키 재방문·방문자 격리·이전 Auth.js 쿠키 무시·OAuth query 없는 이전 UI redirect·인증 API 404·타 origin 차단·저장/결제 실패 복구·주문 중복/경쟁·환불/초기화 통과. 로컬 포트는 기본 샌드박스에서 EPERM이어서 해당 검사만 권한을 받아 실행했어.
- Chromium 핵심 3흐름 통과: 일반 상품 주문→내 공간, low v3 편집/PNG/저장/공유/주문, 네트워크 실패/수정 충돌/사본 복구. 새 제목의 마침표 때문에 처음 일반 주문 테스트의 선택자가 실패했지만 기능 오류는 아니었고, 선택자를 고쳐 그 시나리오만 재실행했어.
- 일회용 PostgreSQL 16의 별도 테스트 DB에서 두 연결의 동일 토큰 동시 전환·비관련 예전 행 보존·저장 충돌·주문/환불 원자성·429 통과. 생성한 컨테이너는 종료/제거했어. 운영 DB를 사용하지 않았어.
- 별도 임시 브라우저 검수: 1440/390 내 공간 캡처를 직접 확인했어. 제목·안내·빈 상태·모바일 줄바꿈·overflow·키보드 초점, 동일 쿠키 재방문·다른 context 격리·HttpOnly/Secure/Lax를 확인했어. 캡처는 Git 제외 `artifacts/2026-10-05-visitor-only/`에 있어.
- 수정 문서의 내부 링크 62개·경로와 diff를 확인했어. 초기 기획의 없어진 임시 검토서 링크는 보관 여부를 명시한 일반 텍스트로 바꿨어.

`check:full`의 검사들은 위 분리 실행까지 모두 통과했어. 실패한 선택자만 수정한 뒤 전체 브라우저/DB/모델 검사를 불필요하게 반복하지 않았어.

삭제한 로그인 전용 CSS 25개 규칙을 추가 정리한 뒤 최종 프로덕션 빌드도 통과했어. 공유·쇼핑 화면의 스타일은 건드리지 않았어.

## 운영 경계

이 기록은 로컬 변경이야. 이번 전환에서 운영 DB·원격 환경변수·공개 배포는 변경하지 않았어. 오래된 `AUTH_*` 비밀값은 사용하지 않으므로 운영 반영 때 정리할 수 있지만 로그인 키를 갱신할 필요는 없어.

실제 Safari/Android·보조 기술·저사양 GPU·느린 네트워크는 후속 검수야. 쿠키는 소유권을 증명하는 bearer capability이므로 유효한 토큰을 복사한 브라우저를 원래 브라우저와 구분할 수 없어. 토큰을 공유 URL에 넣거나 화면/로그로 공개하지 않아.
