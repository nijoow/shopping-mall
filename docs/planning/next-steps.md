# 다음 작업 계획

기준: 2026-10-03 활성 코드 점검. 기간은 실측 견적이 없으므로 날짜로 약속하지 않고 완료 기준에 따라 다음 묶음으로 넘어가.

## 유지할 제품 방향

NIJOOW, 스니커즈 중심 편집숍, 실험적인 매거진형 화면, 데스크톱 우선. 러너 1종·로우탑 1종을 중심으로 의류·잡화는 2D 상품으로 유지해. 소셜 3종은 실제 로그인, 결제·배송·환불은 명시적인 데모야. 디자인·찜·장바구니·데모 주문의 계정 이관을 보존해.

## 확인한 출발점

- 현재 `src/`에는 탐색→3D 편집→저장/공유→장바구니→모의 주문→주문 상태/환불 흐름이 연결돼 있어.
- 상품은 7종, 모델은 runner v1 / low v1 / low v2가 존재해. low v1은 이전 저장 구성 호환용이야.
- 로컬 SQLite와 Cloud PostgreSQL의 공통 도메인 및 동시성 테스트가 있어. 실제 소셜 로그인 완료는 확인된 증거가 없어.
- 반말 후보는 20개 활성 파일의 109줄에서 검색됐어. 멀티라인 문장·동적 오류는 이보다 더 있을 수 있어. 단순 정규식 결과를 전체 문구 개수로 보지 마.
- `/about`의 로컬 SQLite 설명, 예전 백로그의 이메일 기준 계정 연결/포인트/관리자 설명은 현재 코드와 달라.
- 기본 CI에는 브라우저 검증이 없고, 만료 레코드의 물리 삭제 작업과 요청 빈도 제한은 활성 코드에서 확인하지 못했어.

## H0 — 하네스 정리 · 이번 작업

**목표:** 다음 작업자가 같은 실행 환경과 검증 범위로 작업할 수 있게 해.

작업 지침·문서 색인·단일 백로그, Node 기준, check/check:full, 임시 HTTP 서버/DB, 명시적 PostgreSQL 테스트, 에셋 계약, CI 확장, 태그 기반 릴리스 설정을 로컬 반영해. 사이트 문구·서비스 기능 변경과 운영 배포는 이번 묶음에 포함하지 않아.

완료 기준: 명령이 실행되고 실패가 숨겨지지 않으며, 단위/HTTP 검증이 실제 운영 DB를 참조하지 않아. 원격 CI 적용 여부는 로컬 결과와 구분해.

## P0-1 — 사이트 문구와 사실관계 · 다음 구현 추천

**이유:** 첫 방문부터 말투와 제작자 중심 설명이 쇼핑몰 인상을 흐려. 위험이 작은 변경으로 전체 경험을 빠르게 정돈할 수 있어.

- [문구 계획](ui-copy.md)의 화면·서버 메시지·메타데이터를 함께 교체해. 사이트는 절제된 존댓말, 버튼·상태는 짧은 중립 표현을 사용해.
- `/about`의 저장 방식, 에셋 제작 범위, 데이터 보관 안내를 실제 코드와 맞춰. 구현하지 않은 자동 삭제나 실제 판매를 약속하지 마.
- 상품마다 반복되는 제작자 설명은 프로젝트 소개로 정리하고, 실결제·배송이 없다는 안내는 푸터와 주문 결정 지점에 남겨.
- 반복되는 공통 문구만 작은 모듈로 모아. 일회성 문구까지 큰 번역 시스템으로 옮기지 마.
- 문장을 검사하는 도메인 테스트는 오류 코드/상태 검증으로 바꿔. 카피 수정이 비즈니스 로직 테스트를 깨뜨리지 않게 해.

**완료 기준:** 반말 후보 전부 분류, 화면·알림·동적 오류·빈 상태·메타데이터 점검 완료. 결제/환불 오인 없음. 1440/1280/390에서 줄바꿈·버튼 잘림 없음. `check` 통과, 변경된 오류 경로는 HTTP 검증.

## P0-2 — 소셜 로그인 실제 검증

**선행:** H0. 문구 PR과 분리해 재현 증거를 관리해.

- Google/Kakao/Naver 각각 성공, 동의 취소, 오류, 로그아웃·재로그인을 검증해. 콜백은 검증 환경의 실제 URL과 맞춰.
- 게스트 디자인·찜·장바구니·데모 주문과 기존 회원 데이터를 함께 준비해 이관·새로고침·재시도를 확인해.
- 제공자 ID로 신원을 식별하고 서로 다른 제공자를 이메일이나 표시 이름만으로 합치지 않는 기준을 유지해.
- 등록되지 않은 제공자/실패 시 화면에서 이유와 게스트 대안을 알려줘. 실제 OAuth는 계정 소유자의 인증/동의가 필요한 단계에서 협업해.

**완료 기준:** 제공자×성공/취소/실패 증거표, 기존 데이터 유지, 중복 이관 없음, 로그아웃 뒤 다른 사람 데이터 접근 불가. 키 등록/제공자 목록 조회만으로 완료 처리하지 않아.

## P1-1 — 3D 품질과 성능

**선행:** 기본 기능 회귀 검증 유지. 새 기능보다 두 모델의 신뢰도를 먼저 올려.

- 앞코·칼라·혀·끈·패널·밑창을 4개 시점으로 검수해. 겹침, 떠 있는 부품, 비정상 비율부터 수정해.
- 기본/어두운 색상, 레더/스웨이드/메시, 각인 0/8자에서 질감·빛·가독성을 확인해. 사진과 실제 모델의 모습이 일치해야 해.
- 모델 버전별 용량·메시 수·로딩 시간·회전 응답을 측정하고 병목에 맞춰 압축/지연 로딩/재질 설정을 선택해.
- 출발점: runner v1 6,447,352 bytes·83 meshes, low v2 7,158,940 bytes·7 meshes. 구조 수치는 품질 판정이 아니야.
- 현재 제작 스크립트의 고정 출력 경로를 버전별 출력으로 바꾼 다음 새로운 모델을 제작해. 기존 v1/v2 주문을 바꾸지 마.

**완료 기준:** 시점별 화면 승인, 커스텀→저장→재열기→공유→주문 구성 일치, PNG 누락/잘림 없음, WebGL 실패/재시도 정상. 같은 측정 조건의 개선 전후 기록. 기준 기기에서 조작 중 눈에 띄는 끊김이 있으면 완료로 두지 않아.

부품 형태 교체는 두 모델의 기본 품질과 조합의 조화가 입증된 뒤 별도 실험으로 판단해. 품질이 낮아지면 확정된 색·재질·각인 범위를 유지해.

## P1-2 — UX 복구·접근성·브라우저 회귀

**선행:** P0-1. P1-1과 독립 작업 가능하되 공유 컴포넌트의 변경 충돌은 피해야 해.

- 검색/메뉴/확인창의 초점 이동·복귀·Escape, 사이즈 선택·오류 알림·키보드 조작을 검수해.
- 저장 중 이동, 네트워크 실패, 다른 창의 수정 충돌, 재고/금액 변경, 공유 만료 화면을 실제로 재현해.
- 1440/1280 데스크톱을 기본으로 390 모바일에서 편집 패널·버튼·캔버스가 가리지 않는지 확인해.
- 핵심 흐름 3개만 자동 브라우저 검사로 시작해: 일반 상품 주문 / 3D 저장 후 주문 / 저장 실패와 복구. 3D는 캔버스 존재만 검사하지 말고 로딩 성공과 대표 화면을 함께 기록해.

**완료 기준:** 키보드만으로 핵심 흐름 사용 가능, 오류 시 입력 보존, 자동 시나리오가 임시 데이터로 재현 가능. iOS/Android 실기기는 별도 결과로 명시해.

## P1-3 — 공개 데모 데이터 운영

**선행:** H0, P0-2의 계정 이관 기준.

- 빈 DB URL이 fallback을 막는 설정 경계를 테스트하고, 로컬/Cloud/테스트 DB 선택 규칙을 명확하게 해.
- 익명 공간 생성·저장·공유 요청의 빈도/용량 제한과 사용자 안내를 설계해. 서버리스에서도 일관되게 적용되는지 검증해.
- 7일 미접속 게스트와 만료 공유는 현재 조회 거절과 실제 레코드 삭제를 구분해. 정리 작업은 dry-run 목록→대상 확인→범위 제한 실행으로 만든 뒤 운영 적용해.
- 회원 디자인·주문은 익명 만료 규칙으로 삭제하지 않아. DB 백업/복원·모델 버전 보존·최근 실패 확인 방법을 문서화해.

**완료 기준:** 운영 DB를 사용하지 않는 반복 검증, 만료 전후/계정 이관 경계 테스트, 정상 회원 데이터 보존, 429·저장 실패 복구, 복원 절차의 실제 검증.

## P2-1 — 포트폴리오 전달력

**선행:** P0 완료, 3D 품질 승인.

대표 디자인, 공유 미리보기, 프로젝트 소개, 60~90초 시연 흐름을 정리해. 구현 기능과 제작 범위·한계를 사실대로 설명하고 실사용자·매출·성과 수치를 만들지 마. 검색 메타데이터/OG/sitemap 필요성도 공개 카탈로그와 비공개 사용자 경로를 구분해 결정해.

완료 기준: 처음 보는 사람이 모델 편집→저장→모의 주문의 연결을 설명 없이 이해하고, 채용 검토자가 코드·검증·역할 범위를 확인할 수 있어.

## 후순위와 작업 단위

문의·후기·별도 관리자·실결제·배송사 연동·포인트·이메일 회원가입·서로 다른 소셜 계정 연결은 이번 완료 목표를 확장하지 않아.

추천 PR 단위는 **문구/소개 교정 → OAuth 검증/수정 → 새 모델 버전 → 브라우저/접근성 → 데이터 운영 → 소개 자료**야. 각 PR은 재현 화면과 완료 기준을 갖추고, 배포된 사실과 품질 승인을 구분해 기록해.
