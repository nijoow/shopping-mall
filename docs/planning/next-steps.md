# 다음 작업 계획

기준: 2026-10-05 사용자 범위 변경. 코드·검증 증거는 [방문자 체험 전환 기록](../implementation/2026-10-05-visitor-only.md), 이전 구현 근거는 [10월 3일 검토](../implementation/2026-10-03-completion-review.md)를 확인해.

## 확정한 제품 방향

NIJOOW, 스니커즈 중심 편집숍, 실험적인 매거진형 화면, 데스크톱 우선. 러너 1종·로우탑 1종은 색·재질·각인으로 편집하고 의류·잡화는 2D 상품으로 유지해. 실제 결제·배송·재고·환불은 체험용이야. 사이트 문구는 절제된 존댓말·중립 표현을 사용해.

**로그인과 소셜 계정 연동은 전부 제거해.** 디자인·찜·장바구니·모의 주문은 방문자별 **내 공간**에 보관해. `/my-page` 경로는 이전 링크 호환용으로 유지해. 같은 브라우저의 유효한 쿠키로 이어가며, 쿠키 삭제·다른 브라우저/기기·7일 미접속 뒤에는 기존 비공개 목록에 접근할 수 없어. 공유 링크와 PNG 내보내기는 유지해. 공유는 7일간 읽기 전용 스냅샷을 보여주며 원래 방문자의 주문·목록에는 접근할 수 없어.

이 결정은 원래 기획의 소셜 3종·회원 이관·OAuth 실검증 요구사항을 대체해. 네이버 과거 인증 증거는 이력으로 남기고 Google/Kakao의 키 복구를 완료 조건으로 삼지 않아.

## 완료한 묶음 — 방문자 체험 전환

- 로그인 UI·인증 API·Auth.js 의존성·설정·계정 생성/병합 코드를 제거해. 이전 로그인 주소는 OAuth query를 전달하지 않고 내 공간으로 이동해.
- 기존 `nijoow-demo-v2` 쿠키와 workspace ID를 유지해. 유효한 예전 회원 쿠키는 **그 쿠키가 가리키는 공간만** 방문자로 전환하고 디자인·주문·재고·공유를 보존해. 토큰 없는 예전 회원 자료를 일괄 전환하거나 삭제하지 않아.
- 모든 현재 방문자에 요청·용량·7일 미접속 규칙을 적용해. 접근 만료와 물리 삭제를 구분하고, 자동 정리를 구현했다고 안내하지 않아.
- 새로고침·다른 방문자 격리·예전 쿠키 호환·동시 전환·주문 중복 방지·429 복구를 검증해. `check:full`과 별도 PostgreSQL 테스트를 실행하고 내 공간의 데스크톱/모바일 화면을 확인해.

완료 기준: 활성 코드/환경 예시에 OAuth 의존성이 없고 가입 없이 탐색→3D→저장/공유→장바구니→모의 주문→내 공간을 이어갈 수 있어. 기존 개인 자료를 초기화하지 않고, 비공개 목록이 다른 방문자에게 노출되지 않아. 기능과 문서 커밋을 구분해 남겨.

## 다음 순서

1. **운영 반영:** 요청 범위에 맞춰 PR·CI를 확인하고 `operation_limits`를 포함한 운영 스키마를 비파괴 적용한 뒤 배포해. 배포의 정확한 커밋과 주요 경로를 확인해. 로컬 통과를 운영 완료로 부르지 않아.
2. **실기기·성능 검수:** Safari/Android에서 스튜디오 색·재질·각인·PNG·저장 복구를 확인해. 저사양 GPU/느린 네트워크에서 모델 로딩·회전·WebGL 복구를 측정하고 병목이 확인된 경우만 최적화해.
3. **시연 전달력:** [60~90초 가이드](../portfolio/demo-guide.md)대로 탐색→편집→저장→공유→모의 주문을 녹화해. 제작 범위·무료 원본 출처·직접 모델링 범위·검증 한계를 사례 자료에 연결해. 확인되지 않은 매출·이용자·성과를 만들지 않아.
4. **공개 데모 운영:** 운영 DB 백업 후 제한·정리 로그를 확인해. 실제 누적 용량과 사용 패턴을 보고 정리 주기·WAF 필요성을 결정해. 정리 도구는 명시적 대상·dry-run·범위 제한을 유지해.

## 후순위

문의·후기·별도 관리자·실결제·배송사 연동·포인트·회원가입·소셜 로그인 복원·임의 부품 교체는 현재 완료 목표를 확장하지 않아. 부품 형태 교체는 두 모델의 조합 조화와 품질이 입증될 때 별도 실험으로 판단해.
