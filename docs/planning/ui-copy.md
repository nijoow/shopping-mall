# 사이트 문구 교체 계획

기준: 2026-10-03. 교체 기준과 범위를 정리한 뒤 실제 UI·서버·메타·카탈로그에 반영하고 메인 에이전트가 화면을 검토했어. 결과는 최종 검토 기록을 참고해.

## 목표와 말투

쇼핑몰 이용에 필요한 행동·상태를 설명하는 문구로 바꿔. 대화의 한국어 반말 규칙은 사용자와 에이전트 사이에만 적용하고, 사이트에는 적용하지 않아.

- 안내·설명: 절제된 존댓말. `~할 수 있습니다`, `~해 주세요`.
- 버튼·제목·상태: 짧은 중립 표현. `디자인 저장`, `공유 링크 복사`, `저장 중`, `저장 완료`.
- 오류: 확인된 문제와 다음 행동. 원인을 모르면 연결이 끊겼다고 단정하지 않아.
- `만들어봐`, `골라봐`, `담아줘`, `준비하고 있어`, `~야/이야/돼` 같은 말투를 제거해.
- 브랜드의 영문 타이포그래피와 제품명은 유지해도 돼. 영어/한국어를 기계적으로 통일하는 작업은 아니야.
- 실제 결제·배송이 없다는 사실은 숨기지 않아. 과도한 반복은 줄이고 푸터·주문 결정 지점·프로젝트 소개에서 목적에 맞게 안내해.
- 소재 함량·실제 착용감·배송일·재고·제조 품질·성과 등 확인되지 않은 사실을 새로 쓰지 않아.

문구는 실제 화면에서 다듬는 초안이야. 예를 들어 빈 상태는 제목만 바꾸고 끝내지 말고 `디자인 만들기` 같은 바로 수행할 행동을 함께 제공해.

## 사실 교정과 정보 배치

1. **프로젝트 소개:** 현재 운영은 PostgreSQL을 사용해. `/about`의 “현재 개발 버전은 … 로컬 SQLite” 문장은 “저장한 디자인과 주문은 같은 브라우저의 내 공간에서 이어서 확인할 수 있습니다.”처럼 사용자가 필요한 정보로 바꿔. 개발 저장소 설명은 개발 문서에 둬.
2. **제작 범위:** 이미지 생성 상품은 재킷·니트·가방뿐 아니라 바지·모자도 포함해. 소개 페이지의 제작 범위와 출처를 갱신해.
3. **보관:** 공유 링크 7일 만료와 게스트 7일 미접속 처리, DB 물리 삭제를 같은 뜻으로 안내하지 마. 자동 정리를 구현하기 전 “7일 뒤 모든 데이터가 삭제됩니다”를 쓰지 않아.
4. **상품 상세:** `composition`에 반복되는 “포트폴리오를 위한 가상 컬렉션”이 실제 소재 설명을 대신하고 있어. 정보의 제목부터 점검하고 상품에는 확인 가능한 실루엣·편집 범위를 적어. 기술적 제작 설명은 소개 페이지로 옮겨.
5. **모의 흐름:** 결제 선택·완료·환불에는 `모의 결제`, `모의 환불`을 명시해. 도움말을 줄여도 결제·배송 오해를 만들면 안 돼.

## 용어 기준

| 개념               | 표현                                            |
| ------------------ | ----------------------------------------------- |
| visitor workspace  | 방문자별 체험                                   |
| personal space     | 내 공간 — `/my-page` 경로는 호환용으로 유지     |
| design library     | 내 디자인                                       |
| custom editor      | 디자인 스튜디오                                 |
| wish list          | 찜 — 메뉴·빈 상태·버튼의 명칭 통일              |
| checkout / payment | 주문하기 / 모의 결제                            |
| reset              | 체험 데이터 초기화 — 실제 삭제 범위를 바로 설명 |

큰 i18n 의존성을 추가하지 않아. 여러 곳에서 반복되는 완료/실패/데모 안내는 공통 상수로 정리하고, 상품별 카피는 카탈로그에 유지해. 오류 식별은 `DomainError.code`와 HTTP 상태로 유지해.

## 구현 순서와 완료 기준

1. 흐름별 목록을 채우고 중복·사실 오류·말투를 분류해.
2. 공통 문구와 서버 오류부터 교체하고, 카탈로그·화면·메타 순서로 진행해.
3. 현재 테스트의 한국어 메시지 정규식 의존은 오류 코드 검증으로 바꿔. 의미 없는 전 문장 스냅샷 테스트는 만들지 마.
4. `check`와 관련 HTTP 흐름을 검증하고, 화면의 정상/빈/오류/진행 중/완료 상태를 확인해.
5. 1440/1280/390에서 CTA 잘림·줄바꿈·레이아웃, 키보드 초점·읽기 순서를 확인해.

카피 작업은 말투 후보를 모두 검토하고, 잘못된 사실을 교정하고, 실제 청구·배송·데이터 보존 범위를 정확하게 이해할 수 있을 때 완료야. 이 문서 작성만으로 사이트 문구가 바뀐 것은 아니야.
